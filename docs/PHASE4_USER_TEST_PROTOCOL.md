# Phase 4 ユーザビリティテスト手順

実参加者を使って、初見の分かりやすさとhostの進行負荷を確認するための手順です。1回につき[host観察シート](HOST_OBSERVATION_SHEET.md)を1枚使い、氏名や発言の逐語記録は残しません。

## 目的

- プレイヤーが参加後60秒以内に、自分のロールと最初の行動を説明できるか確認する
- 各フェーズの未対応タスクが1画面で分かるか確認する
- hostが優先ルーム、未回答、未投票、未採点を見つけられるか確認する
- AIなし、低速回線、途中切断、hostリロード時に進行が止まらないか確認する

## 実施条件

- host 1人、プレイヤー2〜4人。初回参加者を優先する
- hostは開始前に画面操作を説明しすぎず、通常の進行ガイドだけを使う
- 1回目はAIなしで実施し、必要なら別回でCodex接続確認とAI失敗後の手動引き継ぎを確認する
- 参加者にはテストの目的と、途中で感想を尋ねることだけ伝える。正解や操作場所は先回りして教えない
- 記録は時刻・件数・画面上の詰まりに限定し、個人情報・APIキー・AIの生ログを記録しない

## 実施手順

### 1. 開始前

1. host PCで`cd web`、`npm install`、`npm run host`を実行する。
2. `http://localhost:5173/#host`を開き、必要ならAI設定の「接続確認」を行う。
3. 観察シートの実施情報と開始前チェックを記入する。
4. 参加者へ参加リンクとルームコードだけを共有する。

### 2. 初見理解（60秒）

1. 最初のプレイヤーがロビーに入った時刻を記録する。
2. 参加後60秒以内に、画面を見ながら「自分のロール」と「最初にすること」を説明してもらう。
3. 答えられなかった場合は助けず、どの表示を探したかだけを記録する。
4. hostは通常どおりシナリオを選び、ゲームを開始する。

### 3. 通常進行

1. ブリーフィングで、プレイヤーがロール・シナリオ・準備OKの場所を自力で見つけられるか観察する。
2. 議論で、プレイヤーが「ヒアリング」「要求カード」「仕様書」の入口を自力で使えるか観察する。
3. hostは進行コックピットの優先度、次へ進む前の確認、タイマーを使って進行する。
4. 各フェーズで、プレイヤーが次の行動を尋ねた回数と、hostが画面を探して止まった回数を記録する。
5. AIなしで質問への手動回答、要求カード、仕様書、投票、結果発表まで完走する。

### 4. 異常系（同じ回または別回）

- プレイヤー1人を390px幅で操作し、横スクロールなしで議論導線を使えるか確認する。
- 可能なら1人だけ低速回線相当で参加させ、参加完了までの詰まりを記録する。
- 途中で1人のタブを閉じてhostの切断表示を確認し、同じURLを再訪して復帰できるか確認する。
- hostをリロードし、ゲームコード・フェーズ・保存時刻の復帰通知を確認する。
- Codex利用回では、接続確認の失敗またはAI実行失敗から、再試行または手動対応へ移れるか確認する。

## 合否の目安

| 観点 | 合格条件 | 記録すること |
| --- | --- | --- |
| 初見理解 | 60秒以内にロールと最初の行動を説明できる | 経過秒数、探した場所 |
| フェーズ導線 | 重要な未対応タスクを1画面で説明できる | 質問回数、迷った表示 |
| host巡回 | 優先ルームと理由を説明して開ける | 特定までの秒数、探した場所 |
| モバイル | 390px幅で主要操作が横スクロールなし | 操作不能箇所 |
| AIなし | 手動回答を含めて結果発表まで完走 | 停止回数 |
| 復旧 | 切断・リロード後に同じ進行へ戻れる | 復帰時間、表示された案内 |
| 持ち帰り | 結果画面で学びと次回の一手を言語化できる | アンケート傾向 |

10ルーム相当の優先キューは、40人分の純粋関数テストで順序と計算時間を確認済みです。実参加者テストでは、実際のhostが優先度表示から対応ルームを選べるかを別に測定してください。

## 終了後

1. 観察シートの「次回に変えること」を一つだけ記入する。
2. 参加者には1〜5の匿名アンケートだけを依頼する。
3. 合否ではなく、迷った画面・待った時間・次回に変える行動を次の改善項目へ転記する。
