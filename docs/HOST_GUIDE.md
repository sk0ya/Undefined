# host向け進行ガイド

このガイドは、研修中にhostが画面を探し回らず、ゲームの進行と議論の支援に集中するための短い手順です。

## 開始前（ローカル実行）

1. host PCにNode.js 20+と、ログイン済みのCodex CLIを用意する。
2. リポジトリの`web`ディレクトリで次を実行する。

   ```powershell
   npm install
   npm run host
   ```

3. `http://localhost:5173/#host`を開く。
4. 「🔑 AI設定」で`Codex(host PC)`を選び、「接続確認」が5秒以内に成功することを確認する。失敗した場合は画面に理由が出るので、ブリッジを起動してから再確認する。
5. シナリオを選び、表示された6文字のルームコードを参加者へ共有する。参加リンクをコピーした場合、参加者は公開Pages URLを開く(ホストPCの`localhost`は開かない)。

`npm run host`はゲーム画面とCodexブリッジを同時に起動します。終了するときは同じターミナルで`Ctrl+C`を押します。5173番ポートが別のアプリで使われている場合は、先にそのアプリを停止するか、`REQGAME_HOST_PORT`で別ポートを指定してください。

## 進行中の見る場所

| 場面 | hostが確認すること | 参加者に促すこと |
| --- | --- | --- |
| ロビー | 参加人数、接続状態、シナリオ | ルームコードと名前で参加 |
| ブリーフィング | ロールとシナリオを読めたか | 読み終わったら準備OK |
| ヒアリング・議論 | ルーム優先度、未回答質問、停滞、タイマー | 事実を聞き、例外を質問し、要求カードと仕様書へ反映 |
| 合意形成 | 未投票カード、タイマー | 各カードに賛成/反対を投票 |
| 仕上げ | 仕様書の空欄、編集競合、採点対象 | 文書を確認して仕上げ完了 |
| 結果発表 | 採点、判断の足跡、見落とし、次回の一手 | 学びを一つ言語化 |

仕様書は「Markdownをコピー」で共有用テキストをコピーでき、「Markdownを保存」で`.md`ファイルとして残せます。紙で配る場合は「印刷」を使ってください。

上部のルーム優先度は、接続切れ・未回答・準備状態・停滞をもとに並びます。まず優先度の高いルームを開き、必要なら質問キューやヒントを使います。

## AIを使うとき

- NPC回答、イベント生成、ファシリ補助、採点は画面から直接実行する。
- 実行中は画面を閉じず、完了または失敗の表示を待つ。
- 失敗したら、同じカードの「再試行」または「プロンプトをコピー」で手動対応へ切り替える。ゲームの進行自体は止めない。
- NPC回答はhostが内容を確認してから参加者へ返す。秘密情報を先に開示しない。

Codexブリッジは`127.0.0.1:8787`だけで待ち受け、Codexを一時ディレクトリ・読み取り専用・120秒タイムアウトで実行します。GitHub Pagesの画面を使う場合は、同じhost PCで`npm run codex:bridge`を別途起動し、公開Originを指定してください。

## フェーズを飛ばすとき

通常は「次のフェーズへ」を使います。ステッパーから直接移動する場合は、確認画面に表示される影響を読むこと。

- フェーズ移動でタイマーや準備OKがリセットされることがある
- 投票フェーズを離れると、その時点の投票が確定する
- 未回答質問・未投票・未採点の表示を確認してから進める

## リロード・終了

- hostがリロードした場合、保存されたゲームコード・フェーズ・保存時刻が画面に表示される。
- 復帰後はルームコードと対象ルームを確認し、プレイヤーの接続が戻るまで少し待つ。
- 参加者が同じルームURLをリロードした場合は、保存された名前と参加トークンで自動復帰する。別のルームへ移るときは、新しいルームコードを入力して参加する。
- ブラウザを閉じるとゲームは停止する。再開する場合は同じhost PCでゲーム画面を開き直す。
- 共用PCでは、APIキーを使う方式の保存設定を確認し、終了後に残さない。
