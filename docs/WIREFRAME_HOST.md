# host画面ワイヤーフレーム（P0）

進行中にhostが「今どのルームを、なぜ見るべきか」を最短で判断できることを目的にした、実装確認用のワイヤーフレームです。これは視覚デザインではなく、情報の優先順位と操作の配置を固定するための仕様です。

## 基本レイアウト（デスクトップ）

```text
┌─────────────────────────────────────────────────────────────────────┐
│ REQGAME / ルームコード  ABC123   フェーズ: 議論   残り 08:42   AI: 接続中 │
├─────────────────────────────────────────────────────────────────────┤
│ [次のフェーズへ] [一時停止/再開] [＋5分延長]  参加 8/8  接続 7/8       │
│ 次に確認: 未回答 2 / 未準備 1 / 未採点 0        [詳細を表示]          │
├───────────────────┬─────────────────────────────────────────────────┤
│ 対応が必要なルーム  │ 選択中: ルームA                                  │
│ ───────────────── │ ┌─────────────────────────────────────────────┐ │
│ ● ルームB  未回答2 │ │ ルーム内参加者 / 準備OK                         │ │
│ ● ルームC  切断1   │ │ 質問キュー（未回答）                            │ │
│ ○ ルームA  通常    │ │ 要求カード / 仕様書 / 投票 / 採点               │ │
│                   │ └─────────────────────────────────────────────┘ │
│ [ルームA] [ルームB] │                                                 │
├───────────────────┴─────────────────────────────────────────────────┤
│ 下部ツール: [質問キュー] [NPC回答] [イベント] [ファシリ台本] [AI設定]   │
└─────────────────────────────────────────────────────────────────────┘
```

## 配置ルール

1. 最上段はフェーズ、残り時間、接続状態、ルームコードを固定表示する。
2. その下に通常進行の主操作を1つ置き、時間切れ時は「延長」を主操作に切り替える。
3. ルーム一覧は優先度順に並べ、ラベルだけでなく理由（切断、未回答、未準備、停滞、通常）を表示する。
4. 選択中ルームの詳細は中央に置き、質問・要求・仕様書・投票・採点を同じルームの文脈で開けるようにする。
5. イベントやAI設定の詳細は下部ツールへまとめ、進行サマリーより前面に出さない。

## 状態別の表示

| 状態 | 主操作 | 必ず表示する確認 |
| --- | --- | --- |
| 開始前 | `開始(推奨分)` | 推奨時間、参加人数、未接続人数 |
| 実行中 | `一時停止` | 残り時間、現在フェーズ |
| 一時停止 | `再開` | 停止中であること、再開による影響 |
| 時間切れ | `＋5分延長` | 「延長または次へ」、次フェーズへの導線 |
| AI失敗 | `再試行` / `手動対応` | 失敗理由、プロンプトコピー、適用状態 |
| 直接遷移 | `遷移する` | タイマークリア、準備OKリセット、投票確定など |

## 狭い画面での優先順位

- 横スクロールを発生させず、フェーズと主操作を最上部に残す。
- ルーム一覧は横スクロール可能なタブまたは縦積みにし、優先度ラベルを省略しない。
- 詳細ツールは折りたたみ、質問キューと次フェーズ前チェックを先に表示する。

## 受け入れ確認

- hostが5秒以内に最優先ルームと理由を説明できる。
- 次フェーズへ進む前に、未準備・未投票・未回答・未採点を確認できる。
- AIなしでも質問回答、採点、結果発表へ進める。
- 破壊的な遷移の影響を実行前に確認できる。
