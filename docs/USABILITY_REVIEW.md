# 画面操作レビュー（2026-09-27）

ローカル環境のChromiumで、ホストと参加者を別ブラウザコンテキストとして操作して確認。

## 発見した問題と変更

| 操作・問題 | 変更 |
|---|---|
| 管理者の議論画面で、質問・成果物・台本・AI設定が長い一覧に混在 | 「質問に回答」「ルームの成果物」「進行・イベント」「ホスト用資料」「AI設定」に分割。未回答件数をナビゲーションに表示 |
| 質問や要求を書きながら別タブを開くと入力が消える | 開いた作業画面を保持し、タブを往復しても下書きを維持。管理者の回答欄も同様 |
| 議論フェーズの「いまやること」が次の投票を案内する | 現在のフェーズの目的を表示。次のフェーズの説明は詳細へ移動 |
| 重複名で参加を断られても「接続中」が解除されない | 参加エラー時に入力を再開できるよう修正。接続待ちの中止も追加 |
| コード未入力の入口から参加すると復帰先のコードが保存されない | 参加処理が現在のルームコードを保存するよう修正 |
| 日本語入力の変換確定Enterで要求カードが送信される | IME変換中のEnterでは送信しない |
| PCで入力欄と記録を見るために上下の往復が必要 | 質問・要求の入力と記録一覧を2列に配置。狭い画面では1列に戻す |
| フェーズ変更後に前のスクロール位置が残る | フェーズ切り替え時は画面先頭に戻す |
| 管理者のルーム切り替え時に編集状態が別ルームへ残る可能性 | 仕様書エディタをルームごとに分離 |

## 再現可能な確認

`cd web` で `npm run test:e2e` を実行。

- `e2e/usability.spec.ts`: 重複名の修正、入口から参加後の復帰、下書き保持、IME確定、質問と手動回答、管理者の作業切り替え、390px幅のはみ出し、接続待ちの中止を確認。
- `e2e/game-flow.spec.ts`: 参加から結果発表、共同編集の競合、再接続、AI失敗時の手動対応、複数ルームなどの既存フローを確認。
- 操作テストの画面画像は `web/test-results/` に出力（Git管理対象外）。

下書きは同じタブの再読み込みにも対応（後述）。操作時間や初参加者の理解度は、研修参加者による評価では未計測。

## 追加レビュー

投票・出力・接続切れまで操作範囲を広げ、次の問題を再現して修正した。

| 再現操作 | 問題と修正 |
|---|---|
| 「未投票だけ表示」で最後のカードへ投票 | 「すべて表示」が消えて投票を見直せなかった。フィルター中は解除ボタンを残す |
| 自動保存の応答前にMarkdownをダウンロード | 最新入力が欠けたファイルになった。画面内の下書きを含めて出力する |
| 質問を送ってホストの回答を待つ | 回答待ちを「おすすめ」にし続けていた。要求カードや仕様書など、自分で進められる作業を優先する |
| ホストタブを閉じる | 30秒以上経っても切断が表示されず、送信可能だった。通信が15秒以上届かない場合に再接続を開始する監視を追加（監視周期5秒） |
| ホストを開き直し、参加者をリロードせず復帰 | 再参加用メッセージに初回発行トークンが保持されなかった。受領したトークンで同じ参加者として復帰する |

切断検知後は質問・要求・投票・準備OKの操作を無効化する。仕様書の下書きは保持し、ファイル出力は引き続き可能。再接続後に未保存箇所を再保存できる。切断から検知までの通信保証や、送信ごとの受領確認を追加したわけではない。

仕様書には各項目へ移動する目次も追加。クリップボードが拒否された場合は成功表示を出さず、ファイル保存を案内する。追加のブラウザ確認は既存の操作テストを拡張している。

40人規模の実環境での通信・操作時間・理解度の評価は未実施。画面の大規模データ確認とは区別する。


## 検索・下書き復元・大規模データでの改善

- 要求カード（参加者・管理者）、投票、ヒアリング記録、管理者の質問キューを検索できる。カテゴリ・提出者・回答状況・質問先・ルームなど、画面に応じた絞り込みを追加。全角／半角・英字の大文字／小文字の違いは吸収し、複数キーワードはAND検索する。
- 絞り込みの件数とゼロ件の説明、解除ボタンを表示する。投票済みカードだけが検索に一致する場合も、全体の投票完了とは区別する。
- 質問（宛先を含む）、要求カード（カテゴリ・理由を含む）、ホストの回答、未保存の仕様書を同じタブの再読み込み後に復元する。`sessionStorage`を使い、ゲームごとのルームID・参加者ID・質問IDで分離する。送信済みの入力は復元しない。保存が利用できない環境では入力を止めず、保存不可と表示する。
- 仕様書は編集前の共有内容も記録する。復元時に他の人の変更があれば既存の競合比較を表示し、自動で上書きしない。共有への反映は再保存操作で行う。自分が直前に保存した欄を再編集する際の不要な確認もなくした。
- コード未入力の入口から参加した場合も、成功後のURLにルームコードを反映し、再読み込みで同じルームへ復帰する。
- デスクトップの質問・要求入力フォームは固定表示をやめ、縦に短い画面でも送信ボタンまで自然にスクロールできる配置にした。
- 40人・10ルーム・40質問のデータを実際のホスト画面に載せ、質問の絞り込み・回答と全10ルームの成果物への移動を確認。狭い画面ではルーム優先キューを横スクロールにし、タイマーの詳細設定を開閉できるようにした。

`e2e/search-drafts.spec.ts` は実際のホストと参加者の接続で、17枚のカード検索、入力直後のリロード、管理者回答の復元、仕様書復元時の同時編集、投票中の検索、ゲーム再開始時の下書き分離を確認する。

`e2e/scale-ui.spec.ts` は `test/fixtures/ScaleHost.tsx` のゲームエンジンで生成した40人分のデータを使う画面テストであり、40台の通信負荷試験ではない。テスト時だけ入口を差し替え、通常のアプリや本番ビルドへテスト画面を追加しない。

タブを閉じた後の下書き復元や別端末への下書き移行は対象外。

## 送信確認と誤削除の防止

- 参加者の要求・質問は、送信前には存在しなかった自分の投稿がホストの共有一覧に反映されてから入力を消す。確認中は連続送信を防止し、12秒で確認できなければ下書きを残して一覧の確認と再送を案内する。遅れて反映された場合も確認するが、その間に書き換えた入力は消さない。
- 要求カードの削除は参加者・管理者ともタイトル付きの確認を表示する。キャンセル可能だが、削除確定後の取り消しは未対応。
- 質問のCtrl+Enter送信も日本語変換中には実行しない。
- `e2e/submission-safety.spec.ts` は参加者の質問・要求の送信だけをテスト用に遮断し、入力保持、待機解除、再読み込み後の下書き、再送成功、削除キャンセルと確定をブラウザで検証する。

この送信確認は共有一覧との照合であり、永続的な送信IDによる重複排除ではない。受信済みだが一覧を受け取れない場合や、その状態で再読み込み・再送した場合の重複防止には改善余地がある。
