# 社内プレイテスト：ホスト用ガイド（ネタバレあり）

シナリオ選択で「発売前のゲーム、誰に遊んでもらう？」を選ぶ。既存の質問・仕様書・採点の流れで実施できる。2〜4人のルームで60分を目安に、導入5分、質問と仕様作成45分、採点と振り返り10分を取る。満点の筋道には回答済みの質問が16件前後必要になるため、複数ルームを回す場合はNPC自動回答をオンにすることを推奨する。

## 回答のしかた

4人のNPCをホストまたはNPC自動回答で演じる。最初はopeningだけを伝え、knowledgeのrevealWhenを満たす質問に、その範囲だけ答える。「全部教えて」には冒頭の要求を繰り返し、個別の事情は列挙しない。同義の自然な質問も受け付け、特定の言い回しを当てるゲームにしない。

代替案の確認には各NPCの合意条件を使う。条件を満たした案には明確に承諾し、不足があればその点を答える。口頭で確認した場合も、プレイヤーにそのNPC宛ての質問として記録してもらい、ホストがNPCとして回答を入力する。ホスト宛ての質問（宛先「ホスト」）は進行の案内用で、NPCの事情や承諾の証拠にはならない。提出文書に「確認済み」と書くだけでも証拠にしない。

## 採点

既存のAI採点へシナリオのルーブリックと質問記録が渡る。以下はホストの手動採点・AI結果レビューにも共通する基準。追加の自動点数補正処理はなく、チーム得点はAIが出した値がそのまま表示される。**各軸の点数の合計とチーム得点が一致しているか、減点が講評に書かれているかを必ず確認する。**

- 発見30点：R1〜R6をNPC本人宛ての質問への回答で確認できたら各5点。未質問の推測は0点。
- 反映30点：確認したR1〜R6を具体的要件に反映できたら各5点。曖昧なら2点。未確認なら0点。
- 調整25点：上の5論点。両当事者の事情と案への承諾を記録し仕様に反映すれば各5点。両者の事情は把握済みで案が未確認、または片方のみの承諾なら2点。それ以外0点。
- 具体性15点：手順と担当、実現性、受入条件とスコープを各5点。下記減点後は0点を下限とする。

回答済みの有効な質問がないチームは、上の3軸が0点なので最大15点。質問だけ送って回答を得ていない場合も同じ。仕様の良さだけで発見点を与えない。確認されていないことは未合意として残してよいが、合意済みの得点にはしない。

## 個人目標と全体の衝突

個人目標は各ロール40点満点でチーム得点とは別。次の仕様を採用すると、それぞれ個人20点を得る一方、チームの具体性・実現性から5点ずつ減点する。減点条件はルーブリック本文にも書いてあるため、該当ロールが欠員のルームでもAI採点に反映される。

| 個人目標 | チーム減点の条件 | 調整の例（この場合、衝突する個人目標は未達成） |
|---|---|---|
| PM：人数だけを成功指標にする | 成功指標が参加人数だけ | 初心者の参加数や改善に使えた記録も見る |
| 開発：自由記述1欄だけにする | 終了後の自由記述しかなく観察記録もない | 短い構造化項目や観察記録を併用する |
| UX：完全自由選択だけにする | 対象者別の募集調整を一切しない | 本人の希望を尊重しつつ不足層へ募集する |

欠員ロールの目標は個人採点しないが、同じ仕様には同じチーム減点を適用する。個人目標を譲った場合に、勝手に達成扱いにしない。減点は具体性・実現性の軸内で行い、総合点から再度引かない。前の3軸はそれぞれの証拠条件に従って採点する。業務分析担当の個人目標はチームの目的と一致させてあり、調整役として動く手本のロールになる。

## 動作例としての採点確認

- 質問0件、具体的で実現可能な仕様、衝突目標なし：0 + 0 + 0 + 15 = 15点。
- 同じ仕様で「人数だけ」「自由記述だけ」「自由選択だけ」を採用：0 + 0 + 0 + 0 = 0点。該当する個人目標には各20点。
- R1〜R6の回答を得て具体的に反映、全5論点を両当事者と合意、実現可能、衝突目標なし：30 + 30 + 25 + 15 = 100点。
- 事情だけ発見し、仕様へ反映していない：発見点は得るが反映点は得ない。質問回数による上乗せはしない。

振り返りでは「どの要求をそのまま受けたか」「理由を聞いて何が変わったか」「個人目標をどこで譲ったか」を確認する。採点表やNPCの秘密は開始時に配らない。
